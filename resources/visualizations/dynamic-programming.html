Dynamic Programming — Visual Study Guide

Three interactive visualizations: Fibonacci redundancy, Coin Change table filling, and LCS grid construction.

1. Fibonacci — Recursion Tree

Overlapping Subproblems

Purple nodes are computed fresh. Gray nodes are already cached — DP skips them entirely. Drag n upward to see the gray explosion that makes naive recursion O(2ⁿ).

Description: This visualization shows how Fibonacci recursion expands into a tree of repeated subproblems.
Colors: Purple nodes are first-time computations, while gray nodes are repeated calls that DP would reuse from cache.
Why this happens: Naive recursion recomputes identical values like F(3) and F(2), so the tree grows much faster than the number of unique answers.
How to use: Move the n slider and compare the total recursive calls with the number of unique DP states.
What you learn: DP works when subproblems overlap. Caching turns repeated work into one solved state per value.

2. Coin Change — DP Table

Bottom-Up Tabulation

Watch the recurrence DP[i] = min(DP[i], DP[i−c] + 1) happen one cell at a time. The green cell is the source being read; the orange cell is being computed.

Description: This table builds the minimum-coin answer for every amount from 0 up to the target.
Colors: Green marks the source state being read, orange marks the amount currently being updated, and purple marks values already locked in.
Why this happens: To solve amount i, the table reuses earlier answers such as i-c and adds one new coin.
How to use: Change the target amount, then press Step or Auto-play to watch each DP entry get updated.
What you learn: Bottom-up DP builds bigger answers from smaller solved states, and each cell stores the current best choice.

3. Longest Common Subsequence — DP Table

2D DP

Step through the table cell by cell to see the two rules in action: a character match triggers a diagonal +1, a mismatch inherits the max of the cell above or to the left. After filling, press "Show LCS path" to trace the actual subsequence.

Description: This grid compares two strings and fills a DP table to find their longest common subsequence.
Colors: Green shows a character match, blue shows the current cell, orange shows the dependency cells, and purple highlights the final traced LCS path.
Why this happens: A match extends a smaller solved subsequence diagonally, while a mismatch keeps the better partial answer from top or left.
How to use: Enter two strings, step through the table fill, then press Show LCS path to trace the answer.
What you learn: 2D DP compares prefixes of two strings, and the finished table can be traced backward to recover the actual subsequence.
